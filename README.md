# カリンバ練習

8 音のミニカリンバの練習用 Web アプリです。マイクで弾いた音を拾い、「発音の瞬間」と「音程」が譜面のノーツと合えばヒットになるリズムゲームと、チューナーを備えています。依存ライブラリもビルドもなく、静的ファイルだけで動きます。

## 起動方法

AudioWorklet とマイク (getUserMedia) は安全なコンテキストでしか使えず、ES modules は `file://` では読み込めません。`localhost` で配信して開きます。

```sh
python3 -m http.server 8000
# ブラウザで http://localhost:8000/ を開く
```

Chrome と Safari の最新版で使えます。初回のスタート時にマイクの許可を求められます。

ファイルを更新したあとに古い動きが残るときは、スーパーリロード (Cmd+Shift+R) してください。`http.server` はキャッシュを禁止しないので、ブラウザが古いモジュールを使い続けることがあります。

## 使い方

- **練習**: 曲を選び、速度・モード・スクロール速度を決めて「スタート」。1 小節のカウントインのあと、上から落ちてくるノーツが判定ラインに来る瞬間に、その歯を弾きます。「お手本を見る」は、判定なしで音を鳴らしながらノーツを流します。Esc か「中断」で止められます。
  - 通常モード: 発音のタイミングも判定します (PERFECT ±45ms / GREAT ±90ms / GOOD ±150ms)。
  - 待ちモード: 正しい音を弾くまで進行が止まります。タイミングは判定しません。
- **和音**: 曲選択で「和音あり」と出る曲は、同時に弾く歯が横棒でつながって落ちてきます。ストラム (指を滑らせて 1 回で鳴らす) でも、親指 2 本で同時に弾いてもかまいません。判定は和音ごとに 1 つ (全部当たれば最も悪い判定、欠ければ「和音: 2/3」)。待ちモードでは、和音の歯が全部揃うまで止まり、1 回で揃わなくても残りの歯を弾き足せば進みます。結果画面に「和音 n / m 成功」が出ます。
- **チューナー**: 鳴らした歯の音名、周波数、cent のずれを表示します。8 本それぞれの最後に測ったずれが調律チェック表に入ります (±5 cent 以内が緑、±15 cent 以内が黄、それ以上が赤)。
- **設定**: 調律のプリセット (C4–C5 / C5–C6 / 実測)、A4 の基準、レーンの並び、音程の許容、オクターブ違いの扱い、発音の感度、遅延補正、入力デバイス。

## 調律のしかた

振動する部分 (ブリッジから手前の先端まで) を長くすると音が下がり、短くすると上がります。チューニングハンマーで少しずつ叩いて調整してください。チューナーで 1 本ずつ鳴らし、調律チェック表が緑になれば合っています。

調律を厳密に合わせていない楽器は、設定の「調律の実測」で 8 本の実際の周波数を登録できます。低い音から順に 8 本弾くと、「実測」プリセットとして保存され、その周波数が判定の基準になります。

## 判定の仕組み

1. **取り込み**: `echoCancellation` / `noiseSuppression` / `autoGainControl` をすべて切ってマイクを開きます (ブラウザ既定の処理は伸びる音を消してしまうため)。AudioWorklet が 256 フレームずつ main スレッドへ送り、時刻は `frame / sampleRate` で決めます。マイクの音はスピーカーに出しません。オーディオ機器によっては AudioContext が 96kHz や 192kHz で動くので、解析の前にローパスをかけて 40〜48kHz に間引きます (窓長などの定数が 44.1〜48kHz 前提のため)。
2. **発音検出** (`js/onset.js`): 高域寄りの差分エネルギーが、直前約 40ms の平均より 9 dB (感度で 5〜15 dB) 以上、かつ追従するノイズフロアより 12 dB 以上上がった瞬間を発音とします。不応期は 70ms。減衰中の音では発音は出ないので、同じ音の連打も、新しい打鍵のクリックで検出できます。
3. **音高検出** (`js/pitch.js`): YIN で基音を求め、窓付き DFT のピークで精密化します。カリンバの歯は片持ち梁で、上の倍音が基音の約 6.27 倍・17.55 倍と整数倍にならないため、YIN の谷だけでは約 30 cent ずれます。
4. **残響の除去** (`js/analyzer.js`): 前の歯がまだ鳴っていると 2 音が混ざります。発音の直前に鳴っていた歯の正弦波を最小二乗で当てはめ、発音後の窓から引いてから音高を求めます。同じ歯の連打でも、外挿した残響を引くので新しい音だけが残ります。
5. **確定**: 発音から 25〜95ms の窓で推定し、clarity が 0.8 以上の推定の中央値を周波数とします。推定が 2 個未満なら捨てます。許容 cent 以内の歯に一致したら `PluckEvent` を出します。
6. **和音の検出** (`js/chord.js`): 歯の周波数は既知なので、多重ピッチ推定ではなく「既知の 8 周波数への当てはめ」で、新しく鳴り始めた歯の組を求めます。発音の直前の窓 (残響) と、発音 + 約 110ms に終わる窓の 2 つで、8 本の正弦波の振幅と、目立つ歯の周波数を最小二乗で同時に当てはめます。残響は発音後の窓へ位相ごと外挿して引くので、鳴り続けている歯と、打ち直した歯を分けられます。残った振幅が、外挿した残響の半分以上、かつ新しく鳴った歯の最大から 20 dB 以内の歯を、許容 cent 内であれば組に入れます。当てはめた周波数は歯ごとに覚え、次にその歯の残響を引くときに使います。
7. **判定** (`js/judge.js`): 度数ごとに、同じ度数で未判定のうち時刻差が最小のノーツに当てます。1 回の発音で同じ度数のノーツは 2 つ叩けませんが、違う度数 (和音) ならいくつでも当たります。どのノーツにも当たらない度数は wrong (1 回の発音で数えるのは 1 回だけ)。ヒットは「発音 (onset) と音程」の両方が揃ったときだけで、残響だけで次のノーツが当たることはありません。

## 遅延補正

設定の「自動補正」は、BPM 90 でクリックを 8 回鳴らし、それに合わせてどれかの歯を弾いた発音との差の中央値 (4 回以上聞き取れたとき) を遅延にします。判定には `発音時刻 − 遅延` を渡します。クリックはカウントインと遅延計測にだけ鳴らします。

## 疑似マイク (動作確認用)

URL パラメータで、マイクの代わりに合成音を解析器へ流せます。

| パラメータ | 意味 |
| --- | --- |
| `sim=autoplay` | 譜面どおりの時刻・度数で弾く |
| `sim=wrong` | 度数を +1 ずらして弾く (8 は 7) |
| `sim=silence` | 何も鳴らさない |
| `song=<id>` | 曲を選んだ状態で開く |
| `speed=0.5〜1.25` | 速度 |
| `mode=timed\|wait` | モード |
| `strum=<ms>` | 和音の歯のずらしの最大 (既定 25)。歯ごとに 0〜この値のずらしと ±3 dB の強さの揺れを付ける |

例: `http://localhost:8000/?sim=autoplay&song=twinkle`。画面上部に「疑似マイク」と出ます。`window.__kalimba` に `{ state: 'idle'|'countin'|'playing'|'result', result, events }` が常に入ります。

## テスト

```sh
npm test            # node --test test/ (Node 22、依存なし)
npm run check       # 譜面の検証 (範囲・小節の拍数・和音が押さえられる形か)
```

Node 22 は `node --test test/` のディレクトリ指定をモジュールとして解決するため、`test/index.js` から全テストを読み込んでいます。

## 公開 (Cloudflare Pages)

https://kalimba-practice.pages.dev/ で公開しています。HTTPS なので、スマホのブラウザでもマイクが使えます。

更新するときは、変更をコミットしてから次を実行します。`wrangler` (Cloudflare の CLI) にログインしている必要があります。

```sh
npm run deploy
```

`tools/deploy.sh` は、コミット済みの `index.html`・`_headers`・`css/`・`js/` だけを取り出して、Pages のプロジェクト `kalimba-practice` の本番 (main) に上げます。テストや仕様書は上げません。未コミットの変更があると止まります。 `_headers` は全ファイルを `no-store` にします。ES modules の新旧が混ざると起動しないためです (更新後に、ブラウザが古いモジュールを使い続けて壊れたことがある)。

## 制限

- 和音は、同時に 2〜4 本の歯を弾く前提です (親指 2 本で押さえられる形だけ譜面に入れています)。ストラムが長く (約 60ms 以上) 広がると、遅れて鳴った歯が欠けることがあります。歯ごとの強さが 20 dB 以上違うと、弱い歯は検出されません。
- 和音の検出は合成音でしか試していません。実機のマイク、部屋の響き、歯ごとの減衰の違いでは、鳴り続けている歯を新しい発音と取り違えたり、打ち直しを見逃したりすることがあります。まずは「お手本を見る」と待ちモードで試してください。
- 周りの物音や話し声でも発音検出が反応することがあります。反応しすぎるときは設定で感度を下げてください。
- 音程の許容が広い (50 cent) と、半音離れた歯の区別が甘くなります。
- 残響の除去は、直近 8 秒以内に検出した歯の周波数を手がかりにします。検出できなかった歯の残響は引けません。
- スピーカーから大きな音を出すと、マイクが拾って誤検出します。イヤホンを使うか、メトロノーム音をオフにしてください。
- ブラウザやOSの入力遅延は機種で違います。ずれを感じたら遅延補正を使ってください。
